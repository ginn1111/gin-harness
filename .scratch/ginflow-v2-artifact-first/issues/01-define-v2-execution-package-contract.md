# 01 — Define version 2 Execution Package contract

**What to build:** Establish the version 2 domain contract so Ginflow can recognize and validate a minimal artifact-first Execution Package without changing active version 1 behavior. Define canonical vocabulary, artifact lifecycles, stable keys, approval evidence, package baseline rules, and the architectural decision behind the migration.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] Canonical terms and lifecycle states are documented and used consistently.
- [ ] An ADR records the artifact-first decision and its trade-offs.
- [ ] A minimal approved version 2 package validates through one deterministic seam.
- [ ] Existing version 1 behavior remains unchanged.
